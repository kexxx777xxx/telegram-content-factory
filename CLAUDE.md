# CLAUDE.md — конвенції репозиторію

Читається агентом на початку кожної сесії. Тримати коротким.

## Обовʼязкове правило: журнал дій

**Після кожного змістовного кроку дописати запис у `docs/worklog/YYYY-MM-DD.md`.**
Файл на день, лише дозапис — ніколи не перезаписувати попередні записи.

Формат запису:

```markdown
## HH:MM — <що робив>
**Задача:** <фаза + крок>
**Змінено:** <шляхи до файлів>
**Рішення:** <що вирішено і чому; лише якщо був вибір>
**Перевірено:** <команда → результат; без цього крок не вважається зробленим>
**Відкрито:** <що лишилось незробленим>
```

Не описувати очевидне («створив файл»). Записувати те, чого не видно з diff:
причину вибору, що саме перевірено, що свідомо відкладено.

## Git

Репозиторій: `git@github.com:kexxx777xxx/telegram-content-factory.git` (SSH — HTTPS-пуш не
налаштований, `gh` не встановлено).

**Кожна завершена фаза = один коміт + пуш у `main`.** Перед комітом:

1. `npm run typecheck` — має бути чисто.
2. Перевірити, що не потрапили секрети: `app.env`, ключі, токени, бекапи БД.
3. Оновити `CHANGELOG.md` і `docs/worklog/`.

У повідомленні коміта пояснювати **чому**, а не перелічувати файли — diff і так їх показує.

## Код

- TypeScript strict, ESM, `.js`-розширення в імпортах (NodeNext).
- Спільні типи й zod-схеми — у `packages/shared`, а не дублювати між server і web.
- Доменні енуми оголошені один раз у `packages/shared/src/enums.ts`; Drizzle
  `pgEnum` і zod будуються з тих самих масивів.
- Валідація вхідних даних — zod на межі HTTP, не всередині бізнес-логіки.
- Увесь доступ до `process.env` — тільки через `apps/server/src/config.ts`.
- Логи структуровані (`pino`), з полями `project_id` / `post_id` / `job_id`.
- Секрети ніколи не повертаються клієнту — тільки маска через `maskStoredSecret`.
- Мова інтерфейсу та повідомлень про помилки — українська.

## Чого не робити

- Не зберігати опубліковані тексти й зображення: після публікації лишається
  лише `permalink`. Див. `docs/adr/0002-telegram-as-content-store.md`.
- Не хардкодити ID моделей — брати з каталогу провайдера.
- Не покладатись на промпт там, де правило можна форсувати кодом
  (санітизація SVG — приклад).
- Не додавати Redis чи зовнішній брокер: черга живе в Postgres.
- **Не читати `node_modules`** — ні рекурсивним пошуком, ні обходом дерева.
  Пошук по коду завжди обмежувати `apps/`, `packages/`, `docs/`. Потрібен API
  залежності — дивитись її `.d.ts` за точним шляхом, а не сканувати теку.

## Команди

```bash
docker compose up -d db     # тільки база, для локальної розробки
npm run db:migrate          # застосувати міграції
npm run dev                 # server (:3000) + web (:5173)
npm run typecheck           # усі воркспейси
npm test                    # vitest
npm run db:generate         # згенерувати міграцію після зміни schema.ts
```
