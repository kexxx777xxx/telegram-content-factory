# Промпти

## Пʼять дій

| Дія | Що робить | Коли викликається |
| --- | --- | --- |
| `topics` | генерує нові теми для банку | банк просів нижче `topics_buffer_min`, або JIT перед постом |
| `post_text` | пише текст поста за темою | генерація поста |
| `svg` | малює 16:9 схему | `image_mode = svg` |
| `svg_repair` | лагодить невалідний SVG | санітайзер відхилив результат `svg` |
| `image_prompt` | пише промпт для image-моделі за текстом поста | `image_mode = image_model` |

## Успадкування

Промпт для конкретного кроку ланцюжка резолвиться так:

```
step.prompt_override    (крок ланцюжка вказує конкретний prompt_id)
        ↓ якщо немає
project prompt (action) (scope = 'project', той самий project_id)
        ↓ якщо немає
global default (action) (scope = 'global')
```

Це і є відповідь на «під кожну модель свій промпт» без вибуху складності. 90% проєктів не
чіпають нічого. Якщо конкретна `lite`-модель у хвості ланцюжка потребує спрощеної інструкції,
override вішається саме на її крок, а не на весь проєкт.

Реалізація — `apps/server/src/prompts/resolve.ts` (фаза 2).

## Версіонування

Редагування промпта **не мутує рядок**. Створюється новий із `version + 1`, старий лишається
назавжди. Кожен пост записує в `generation` використані `prompt_id@version` і модель.

Це єдині дані, що переживають публікацію (див.
[ADR 0002](adr/0002-telegram-as-content-store.md)), і єдиний спосіб заднім числом пояснити,
чому якість просіла з певної дати.

## Змінні шаблонів

Єдине джерело правди — `packages/shared/src/variables.ts`: `COMMON_VARIABLES` (доступні в **кожній**
дії) плюс `ACTION_VARIABLES` (свої для дії), разом — `promptVariables(action)`. Там сказано, що
підставляється і **яке налаштування це дає**. Той самий запис адмінка малює як «Довідник змінних»
під полем промпта, тож довідник не може розійтись із кодом.

Спільні змінні передаються з одного місця — `projectVariables()` у `apps/server/src/prompts/variables.ts`
— і додаються до **кожного** виклику. Раніше кожен виклик передавав лише те, що згадував його
власний дефолтний промпт: `{{persona}}` в промпті ілюстрації мовчки ставав порожнім рядком, тож
довідник, зібраний із тих наборів, описував би дефолти, а не можливості.

| Змінна | Джерело |
| --- | --- |
| `{{topic}}` | назва теми з банку |
| `{{persona}}` | `projects.persona` — голос автора |
| `{{language}}` | `projects.language` |
| `{{hashtags}}` | `projects.hashtags`; до поста їх дописує код, у промпті — щоб модель їх не писала |
| `{{style}}` | стиль ілюстрацій: проєкт → глобальне налаштування → вбудований |
| `{{maxChars}}` | `projects.post_max_chars` мінус хвіст хештегів — скільки лишається на текст |
| `{{count}}`, `{{existingTopics}}` | скільки тем просити і які вже є (дія `topics`) |
| `{{postText}}` | готовий текст поста без розмітки (дія `image_prompt`) |
| `{{error}}`, `{{svgSource}}` | причина відмови санітайзера і відхилений SVG (дія `svg_repair`) |
| `{{imagePrompt}}` | результат `image_prompt` (дія `image`) |

## Правила, які форсуються кодом, а не промптом

Модель не можна просити гарантувати інваріант — її треба перевіряти. У промпті це лишається як
підказка, але дотримання забезпечує код:

- **Без тексту в SVG.** Вузли `<text>` і `<tspan>` видаляє санітайзер.
- **Формат 16:9.** `viewBox` перезаписується на `0 0 1200 675`.
- **Безпека SVG.** `<script>`, `<foreignObject>`, зовнішні `href`, DOCTYPE/ENTITY видаляються
  незалежно від того, що написано в промпті.
- **Хештеги.** Їх дописує `withHashtags()` перед відправкою, а хвіст тегів, який модель написала
  сама, зрізає `stripTrailingHashtags()`. Промпт просить їх не писати — це підказка, не гарантія.
- **Довжина.** Текст понад `post_max_chars` (разом із хештегами) не зберігається взагалі: пост
  лишається незавершеним, а наступний захід пише текст заново. Ілюстрація при цьому не
  перемальовується. Див. `docs/adr/0008-post-format-enforced-by-code.md`.

Деталі — `apps/server/src/media/svg/sanitize.ts` (фаза 6).

## Ліміти Telegram, які впливають на текст

- Підпис до фото — 1024 символи; повідомлення — 4096. Довший текст publisher розбиває на
  фото + окреме повідомлення.
- Дозволені лише whitelist-теги Telegram HTML; решта екранується.

Скільки просити в моделі — налаштування проєкту **«Довжина поста, символів»**. У промпт іде не
воно, а `{{maxChars}}` — залишок після хвоста хештегів, які дописуються при публікації. Раніше в
промпті стояло число 1024, і «пости трохи коротші» вимагало правити текст промпта. Розбиття все
одно робить код: понад 1024 символи виїжджають окремим повідомленням під фото, і промпт цього не
вирішує.

Ліміт — правило, а не побажання: текст понад нього відхиляється (`postOverflow()`), і пост не
стає готовим, доки не буде коротшого.

## Звідки береться `{{style}}`

Три рівні, зверху вниз:

1. поле проєкту **«Стиль ілюстрацій»** (вкладка «Моделі і промпти», картка «Голос каналу»);
2. **Налаштування → Моделі і промпти → «Стиль ілюстрацій за замовчуванням»** — спільний для всіх
   проєктів, які свого не задали;
3. вбудований `BUILTIN_STYLE` із `prompts/defaults.ts`, якщо порожні обидва.

Ланцюжок вирішується в одному місці — `resolveStyle()` у `services/settings.ts`. Раніше другого
рівня не було: вбудована константа підставлялась просто з коду, і на питання «звідки цей стиль»
адмінка не відповідала ніяк. Змінна підставляється в дії `svg` та `image_prompt`.
